# 小火箭配置

一份可以给别人用的 [Shadowrocket](https://apps.apple.com/app/shadowrocket/id932747118) 配置。文件里没有节点、没有订阅、没有账号。导入后在首页加上你自己的节点或订阅，规则就会生效。

总配置改自 [LingJingMaster/Shadowrocket-Rules](https://github.com/LingJingMaster/Shadowrocket-Rules)。`AI.list`、国内、谷歌这些名单仍放在上游和 [blackmatrix7/ios_rule_script](https://github.com/blackmatrix7/ios_rule_script)，由小火箭自己拉取。这个仓库发布改过的 `Shadowrocket.conf`，并另附一份同规则的 `Clash.yaml`。

配置地址：

```text
https://raw.githubusercontent.com/ibalbal/shadowrocket-rules/main/Shadowrocket.conf
```

## 和上游的差别

| 项目 | 本配置 |
| --- | --- |
| AI 流量 | `AI.list` 直接走 `PROXY`，也就是首页当前选中的节点 |
| DNS | 只问 `https://cloudflare-dns.com/dns-query#proxy` |
| 备用 DNS | 同一条 Cloudflare DoH，不另备 Google |
| 直连域名 | `dns-direct-system = false`，默认不走系统 DNS |
| DNS 劫持 | `hijack-dns = *:53`，53 端口的查询都交给小火箭 |
| 更新地址 | 指向本仓库的 Raw 链接 |

其余策略组、名单和上游保持同步。GitHub Actions 每天 **北京时间 03:00** 拉取上游，再套上表里这些改动。也可以在 Actions 里手动跑 `sync upstream`。

## 导入

需要 iPhone 或 iPad 上的 Shadowrocket。这个文件是小火箭的配置格式，不要拿去当 Clash、Surge 或 sing-box 的订阅。

1. 复制上面的配置地址。
2. 打开小火箭，底部进入 **配置**。
3. 点右上角 **+**，粘贴链接，下载。
4. 点刚下好的配置，让它变成正在使用的那一份（左侧出现勾）。
5. 回到首页，添加你自己的节点，或添加订阅。
6. 给节点做连通性测试，选一个能用的，打开首页开关。

订阅和节点加在首页。本文件的 `[Proxy]` 是空的，更新配置时不会替你保管节点。

## Clash

同一套策略组和分流另存为 `Clash.yaml`，给 Clash Meta 内核用，包括 Clash Verge、Mihomo Party、Stash。经典 Clash Premium 不能用这份文件。

```text
https://raw.githubusercontent.com/ibalbal/shadowrocket-rules/main/Clash.yaml
```

1. 在客户端里新建配置，填上面的地址。
2. 文件里没有节点。下载到本地后，打开 `proxy-providers` 那一段注释，填上你的订阅地址，再导入本地文件。节点会进入 `PROXY` 和各地区组。
3. 打开 `PROXY` 组，选中要使用的节点。它对应小火箭首页当前节点。AI、漏网之鱼、非中国名单都看这个组。
4. 其他策略组的默认出口和下面的表一致。

Clash 没有小火箭的这几项，文件里是这样处理的：

- `google.cn` 和 `g.cn` 不能自动跳到 `google.com`。这两条域名改为进入「谷歌服务」。
- 上游名单里的 `USER-AGENT`，以及香港银行名单里的一条 `URL-REGEX`。Clash 加载时会跳过这些行，域名和 IP 规则还在。
- 没有拦截代理连接的 QUIC。
- 默认不打开 TUN，也不占用 53 端口。在客户端里打开 TUN 之后，才相当于小火箭接管整机流量并劫持 53 端口。

DNS 按本仓库的写法：只问 Cloudflare DoH，并且这条查询走 `PROXY`。普通直连域名不问系统 DNS。`Shadowrocket.conf` 的 `[Host]` 里交给系统的名字仍走系统 DNS。节点自己的域名用 `1.1.1.1` 解析，避免解析和代理互相等待。

每天 03:00 的自动同步只重写 `Shadowrocket.conf`，不会改 `Clash.yaml`。

## 首页节点和策略组

小火箭里三个词会反复出现：

- `PROXY`：首页当前选中的那一个节点。首页换节点，所有写成 `PROXY` 的流量一起换。
- `DIRECT`：直连，不进代理。
- `REJECT`：拒绝连接。

**AI 不看「🤖 AI 服务」这个组。** `AI.list` 的出口写死为 `PROXY`。在策略组里改「AI 服务」，ChatGPT、Claude 以及其他命中这份名单的流量不会跟着变。要换 AI 的出口，在首页换节点。

换好节点后，用浏览器打开下面页面，看当前出口：

- [Claude 检测](https://ip.net.coffee/claude/)
- [GPT 检测](https://ip.net.coffee/gpt/)
- [WebRTC UDP 泄露检测](https://ip.net.coffee/webrtc/)

测 WebRTC UDP 时，浏览器要先装扩展插件。不会装的话，安装一个指纹浏览器，再用它打开上面的页面。

其他服务可以在 **首页 → 策略组**（或配置里的策略组）里改。下面「默认」一列是导入后不做任何改动时的出口。

| 策略组 | 默认 | 可以改成 |
| --- | --- | --- |
| 🚀 节点选择 | `PROXY` | 某个地区组、直连、拒绝 |

| 🔍 谷歌服务 | `PROXY` | 日本、香港、节点选择、直连 |
| 📹 油管视频 | 节点选择 | `PROXY`、直连、拒绝 |
| Ⓜ️ 微软服务 | 节点选择 | `PROXY`、直连、拒绝 |
| 📲 电报消息 | 节点选择 | `PROXY`、直连、拒绝 |
| 🐱 代码托管 | 节点选择 | `PROXY`、直连、拒绝 |
| 🍎 苹果推送 | 节点选择 | `PROXY`、直连、拒绝 |

## 节点名称

香港、台湾、日本、美国、其他地区是自动测速组。节点名要带地区字，才会进对应组。测速地址是 `http://www.gstatic.com/generate_204`，间隔 600 秒。

自动测速还会跳过倍率高于 `1x` 的节点。名字里出现 `1.5x`、`2x`、`2.0X`、`x2`、`×1.5`、`2倍`、`倍率 1.5` 这类写法时，不会被选中。`1x`、`1.0x`、`0.5x`，以及名字里没写倍率的节点仍然可以。首页手动选中的节点不受这条限制。

| 分组 | 名称里出现这些就会进去 |
| --- | --- |
| 香港 | `🇭🇰`、`HK`、`Hong`、`香港`、`深港`、`沪港`、`京港`，以及单独的「港」 |
| 台湾 | `🇹🇼`、`TW`、`Taiwan`、`台北`、`台湾`、`台灣` |
| 日本 | `🇯🇵`、`JP`、`Japan`、`Tokyo`、`日本`、`东京`、`大阪` |
| 美国 | `🇺🇸`、`US`、`USA`、`America`、`美国`、`洛杉矶`、`西雅图`、`纽约` 等 |
| 其他 | 上面都没挨上的节点 |

「港」一个字就会被算进香港。节点名叫「日本-香港中转」时，会进香港组，不会进日本组。一个节点只放一个地区名最稳妥，例如 `🇯🇵 日本 01`、`🇺🇸 美国 02`。

地区组默认不参与分流。只有你在策略组里手动改成日本、香港、美国这些组时，才会用到自动测速和上面的倍率限制。首页若已经选中一个具体节点，AI、谷歌、券商、漏网之鱼和非中国名单都走这个节点。

## DNS

这是本配置里最容易踩坑的部分。

- 解析默认只走 Cloudflare 的 DoH：`https://cloudflare-dns.com/dns-query#proxy`。末尾的 `#proxy` 表示这条 DNS 也从代理出去。
- 备用 DNS 是同一条，没有第二条公共 DNS。
- `dns-direct-system = false`：普通直连域名也不问系统 DNS，同样去问上面这条 DoH。
- `hijack-dns = *:53`：程序自己连 53 端口时，查询被小火箭拿走。
- IPv6 关闭。
- 代理连接屏蔽 QUIC（`block-quic = all-proxy`），YouTube 等会退回 TCP。

`[Host]` 里有一些例外，这些名字仍交给系统 DNS：局域网和反向解析（`*.local`、`*.in-addr.arpa`、`*.ip6.arpa`），以及 `*.icloud.com`、`*.icloud-content.com`、`*.apple-cloudkit.com`、`*.cdn-apple.com`、`*.mzstatic.com`。微信本机回调 `localhost.weixin.qq.com` 固定到 `127.0.0.1` 并直连。

这样做是为了少把域名查询暴露给本地网络，也避开一部分 DNS 污染。代价是：**首页没开连接、节点失效，或 Cloudflare DoH 本身不可达时，国内网站和 App 也会打不开**，因为它们的解析同样要绕进代理。公司网、校园认证、酒店门户、部分银行和券商 App 也可能异常。

先确认首页节点可用，再判断是规则问题还是 DNS 问题。

## 更新

小火箭里更新这一份配置时，用本仓库的地址。不要改成上游的 Raw 链接，否则 AI 和 DNS 会回到上游的写法。

更新的是总配置里的策略和规则写法。各 `RULE-SET` 的名单由小火箭按链接单独拉。每天 03:00 的自动同步只保证「总配置仍带着上面的几处改动」，不会把你首页里的节点提交到 GitHub。

`google.cn` 和 `g.cn` 会被改写到 `google.com`。HTTPS 改写要在小火箭里安装并信任它的 CA 证书。不装证书不影响其他规则。证书只给这份配置里列出的 `*.google.cn` 使用。

## 仓库里有什么

| 文件 | 作用 |
| --- | --- |
| `Shadowrocket.conf` | 给小火箭导入的总配置 |
| `Clash.yaml` | 同一套规则的 Clash Meta 配置 |
| `customize.py` | 下载上游总配置，并改写更新地址、DNS、DNS 劫持和 AI 出口 |
| `.github/workflows/sync.yml` | 每天北京时间 03:00 跑上面的脚本，有变化就提交 |

本地重做一次配置：

```bash
python3 customize.py \
  "https://raw.githubusercontent.com/ibalbal/shadowrocket-rules/main/Shadowrocket.conf" \
  Shadowrocket.conf
```
